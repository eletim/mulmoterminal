## 2. 並べ替えの方針

「よく使われる順」の判断根拠は、**リリースで実際に要望が来た順**（issue と changelog）と
**セットアップ直後に必ず触るもの**。

### config.md

今の並びは「設定モーダル → グローバル設定 → 個別設定 → プロジェクト設定 → script.json → 環境変数」で、
`config.json` の全キー表が2番目に来る。読み手はキー一覧を読みに来るのではなく、**やりたいこと**を探しに来る。

1. まず触るもの — テーマ / フォントサイズ / 通知音 / 設定モーダルの全体像
2. ターミナルの操作感 — Enter の挙動 (`terminalSubmit`) / 選択したらコピー / キーボードショートカット / フォント
3. プロジェクトごとの見分け — 名前バッジと色 / xterm パレット / 並び順
4. ヘッダーのカスタマイズ — ボタン / チップ / Skill 絞り込み
5. 別のモデルで動かす — providers
6. 参照 — 全キー表 / script.json / 環境変数

### features.md

4本柱そのものは維持する（探しやすさに効いている）が、**柱の中の行を頻度順**にする。
「並行ターミナル」「状態の色」のような毎日見るものが先、「MCP サーバ」「音声入力」のような
使う人だけが使うものを後ろへ。

### 見出しの表現

`{#anchor}` を持つ見出しは **ID を変えない**（changelog と他ページから張られている）。
表現だけ、読み手が検索しそうな言葉に寄せる。例:

- 「ロスターの表示行数（`cockpitLines`）」→「ロスターの1行が長すぎる / 短すぎる（`cockpitLines`）」
- 「Enter — 送信と改行（`terminalSubmit`）」→ 現状維持（すでに症状で引ける）
- 設定キー名は見出しから消さない。`grep` で来る読み手がいる

**必ず検証する**: 並べ替えのあと、ページ内リンクとページ間リンクが全部生きていること。
`{#...}` の無い見出しを書き換えるとアンカーが変わるため、書き換える見出しには ID を付ける。
