## If you only read one thing

**Upgrade.** Nothing to configure. Two problems this fixes were invisible by construction — they made
things look *empty* rather than broken:

- A session whose transcript grew past ~512 MB showed **no title, no tool timeline, and a cost of
  $0**. Nothing errored. It read exactly like a session you had just started.
- Opening the terminal list **on your phone** could show **no sessions at all**, timing out after 30
  seconds.

```bash
npx mulmoterminal@latest
```

One thing is new and visible straight away: the Files editor now colours `.vue`, `.py`, `.rs` and
friends.

## Long sessions stop reading as empty ones

**Nothing to configure.**

### What was wrong

`fs.readFile(file, "utf8")` throws once a file passes about 512 MB — **regardless of what is in it**.
That is V8's maximum string length, not a memory limit, and a Claude transcript on a working machine
reaches 585 MB.

Nine places read a whole transcript that way. Each one caught the error and returned "nothing here".
So the sessions you had used the most — the long ones, the ones worth looking back at — were the ones
that rendered as blank.

### How to tell you have the fix

Open your longest-running session and look at the roster row and the Activity timeline.

| Before | After |
|---|---|
| No AI title, or the row is blank | The title and the latest turn are there |
| Activity timeline empty | The tool history is there |
| Cost reads `$0` | The real figure |

If your sessions are all small, you would never have seen this — and nothing changes for you.

## The usage gauge cleans up after itself

**Nothing to configure.**

The 5h / 7d gauge reads Claude's windows by starting one hidden session. Three things about that
session changed.

### It no longer leaves sessions behind

Its transcripts used to pile up in `claude --resume` — one reporter had 41 of 50 listed sessions come
from it. Hiding them from MulmoTerminal's own list was only half the answer, because `--resume` reads
the transcript directory itself. Now the probe deletes its own file, and the ones left by older
versions are swept **once per workspace** the first time you run 2.6.0.

**Check it:** run `claude --resume` in your workspace. Entries titled *"reply with the single
character: ."* or *"Single character response task"* should be gone.

### It stops as soon as it has the answer

It used to hold a live `claude` process for the full 90-second timeout even after the numbers had
arrived — and while that was happening, every open browser polled the server every 6 seconds instead
of every 2 minutes.

### It no longer shows you a figure that has expired

If a reading's reset time has passed, the window it describes has already rolled over — so the
percentage belongs to a budget that no longer exists. Those are dropped now, and dropping them is
what makes the "why is this missing" line appear:

| What you see on hover | What it means |
|---|---|
| the `claude` command was not found on PATH | Install `claude`; the gauge recovers on its own |
| this account reports no 5h / 7d windows (API-key billing) | Structural — API-key billing has no windows |
| the last check got no answer. Retrying, less often each time | Unanswered trust prompt, expired login, or a slow machine |

Before this, a cached figure suppressed that line — so uninstalling `claude` left yesterday's
percentage on screen, saying nothing.

**One thing to know:** the check runs when the gauge refreshes, roughly every 2 minutes. It is not a
ticking clock, so a window that expires while you are away is dropped at the next refresh, not the
instant it lapses.

## The Files editor colours real languages

**Nothing to configure.** Open a `.vue` file in the Files view — it has syntax colours now.

The editor previously knew three modes: markdown, JS/TS, JSON. Everything else opened as plain text,
which is why `.vue`, `.py`, `.rs`, `.css` and `.yaml` were all colourless.

| Mode | Extensions |
|---|---|
| html | `.html` `.htm` **`.vue` `.svelte` `.astro`** |
| css | `.css` `.scss` `.less` `.sass` |
| python | `.py` |
| rust | `.rs` |
| go | `.go` |
| java | `.java` |
| shell | `.sh` `.bash` `.zsh` |
| sql | `.sql` |
| xml | `.xml` `.svg` |
| yaml | `.yaml` `.yml` |

## Your phone can see the session list again

**Nothing to configure.**

If you opened the terminal list on your phone and got **nothing** — not a short list, nothing, after
about 30 seconds — this is the fix. A field introduced in 2.5.3 reached Firestore as `undefined`, and
that rejects the *whole* document, so the reply carrying the list was never written.

**Check it:** open the phone view. The list is there.

### And a host that has gone quiet now says so

The Mac's toolbar could stay **Online (green)** while your phone said **offline**, with keeping the
tab open making no difference. The host now notices that its own presence updates have stopped
landing and turns red, so both ends agree about whether you can reach it.

Reference: [Using it from your phone](phone.html) · [Mobile notifications](notifications.html)

## Smaller things

- **`npx mulmoterminal@latest`** is now used everywhere in the docs and in `init`'s closing hint.
  Without `@latest`, `npx` may run a cached older copy — the most common cause of "I upgraded and
  nothing changed".
- Windows CI resolves preset paths before comparing them, closing a gap left in 2.5.3.
