## 長いセッションが「空」に見えなくなる

**設定することはありません。**

### 何が壊れていたか

`fs.readFile(file, "utf8")` は、ファイルが約 512MB を超えると**中身に関係なく** throw します。
メモリ制限ではなく V8 の文字列長の上限です。実際に使っているマシンの Claude transcript は 585MB に達します。

transcript を丸ごと読む経路が 9 か所あり、**どれも例外を catch して「何も無い」として返して**いました。
つまり、**いちばん使ったセッション**——長く、後から見返す価値のあるもの——が、空として描画されていました。

### 修正が入っているかの見分け方

いちばん長く動かしたセッションのロスター行と Activity timeline を見てください。

| 修正前 | 修正後 |
|---|---|
| AI タイトルが出ない／行が空 | タイトルと直近のターンが出る |
| Activity timeline が空 | ツール履歴が出る |
| コストが `$0` | 実際の数字 |

セッションが全部小さい人には、そもそも起きていなかった問題です（何も変わりません）。

## 使用量ゲージが後片付けをする

**設定することはありません。**

5h / 7d のゲージは、隠し Claude セッションを 1 つ起動して数値を読みます。そのセッションについて 3 点変わりました。

### セッションを残さなくなった

以前は `claude --resume` に溜まっていました（報告者の環境では一覧 50 件のうち 41 件）。MulmoTerminal 側の
一覧から隠すだけでは半分で、`--resume` は transcript のディレクトリを自分で読むためです。probe は自分の
ファイルを消すようになり、**古い版が残した分もワークスペースごとに一度だけ**掃除されます（2.6.0 の初回起動時）。

**確認方法:** ワークスペースで `claude --resume` を実行します。*「reply with the single character: .」*や
*「Single character response task」*といった項目が消えているはずです。

### 答えが来た時点で終わるようになった

以前は、数値が届いたあとも 90 秒のタイムアウトまで `claude` プロセスを生かしたままでした。その間、開いている
ブラウザは 2 分間隔ではなく **6 秒間隔**でサーバを叩き続けます。

### 期限切れの数字を出さなくなった

リセット時刻を過ぎた数値は、すでに切り替わった窓のものなので、**いまについて何も言っていません**。
そういう窓は表示しなくなり、そして**表示しなくなることが「出せない理由」を出すきっかけ**になります。

| hover で出る文言 | 意味 |
|---|---|
| the `claude` command was not found on PATH | `claude` を入れれば再起動なしで復帰します |
| this account reports no 5h / 7d windows (API-key billing) | 構造的な理由。API キー課金には報告すべき窓がありません |
| the last check got no answer. Retrying, less often each time | 信頼プロンプト未応答、ログイン切れ、起動が遅い |

これまではキャッシュされた数字がこの行を抑えていたので、`claude` をアンインストールしても**昨日の
パーセンテージを黙って出し続けて**いました。

**1 つ知っておくこと:** 判定はゲージの更新時（およそ 2 分間隔）に走ります。時計を刻んでいるわけではないので、
離席中に切れた窓は「切れた瞬間」ではなく次の更新で消えます。

## Files のエディタが実際の言語に色をつける

**設定することはありません。** Files ビューで `.vue` を開くと色がついています。

エディタが知っていたモードは markdown / JS・TS / JSON の 3 つだけで、それ以外はプレーンテキストとして
開いていました。`.vue` も `.py` も `.rs` も `.css` も `.yaml` も色が無かったのはそのためです。

| モード | 拡張子 |
|---|---|
| html | `.html` `.htm` **`.vue` `.svelte` `.astro`** |
| css | `.css` `.scss` `.less` `.sass` |
| python | `.py` |
| rust | `.rs` |
| go | `.go` |
| java | `.java` |
| shell | `.sh` `.bash` `.zsh` |
| sql | `.sql` |
| xml | `.xml` `.svg` |
| yaml | `.yaml` `.yml` |

## スマホからセッション一覧が見えるようになる

**設定することはありません。**

スマホでターミナル一覧を開いて**何も出ない**（短い一覧ではなく、30 秒ほど待って空）状態だったなら、これが
その修正です。2.5.3 で入ったフィールドが `undefined` のまま Firestore に届き、それは**ドキュメント全体が
拒否される**ため、一覧を運ぶ返信そのものが書き込まれていませんでした。

**確認方法:** スマホ表示を開きます。一覧が出ます。

### 応答しなくなったホストが、そう言うようになった

Mac のツールバーが **Online（緑）**のままなのに、スマホからは **offline**、しかもタブを開いていても直らない
——という状態がありました。ホストは自分の presence 更新が届かなくなったことを検知して赤くなるので、
両端の言うことが一致します。

リファレンス: [スマホから使う](phone.html) · [スマホ通知（Web Push）](notifications.html)

## 細かいもの

- ドキュメントと `init` の最後の案内を、すべて **`npx mulmoterminal@latest`** に統一しました。`@latest` が
  無いと `npx` はキャッシュした古い版を動かすことがあり、「上げたのに変わらない」の最多の原因です。
- Windows の CI が preset のパスを比較前に解決するようになりました（2.5.3 で残っていた漏れ）。
